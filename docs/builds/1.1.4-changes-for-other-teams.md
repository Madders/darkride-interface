# Darkride 1.1.4: what changes for other teams

darkride-builds now carries Caitlyn's `v1.1.4-beta` (`7c3e12631c`), merged on branch `darkride-builds-1.1.4`. This
page lists what 1.1.4 changes for anyone running, scripting against or building Darkride, compared with 1.1.3.1, and
what darkride-builds changed in the merge. Caitlyn's release notes:
<https://github.com/caitlynmeeks/darkride-interface/releases/tag/v1.1.4-beta>.

## Network protocol

- **No packet version changed.** `PacketHeaders.h` and `versionForPacketType()` are the same as in 1.1.3.1, so the
  protocol signature is the same: 1.1.3.1 and 1.1.4 clients and servers connect to each other.
- Every stream that goes on the wire is now pinned to one format (`libraries/shared/src/shared/WireStream.h`: Qt 5.15
  stream version, double-precision floats, big-endian), so a Qt 6 build and a Qt 5 build write the same bytes. On a Qt 5
  build that is what was written before.
- The domain list request sorts its node types, so the same request is the same bytes on every build.
- **Update world servers too.** The fix for clicks and bursts in voices after someone joins is in the 1.1.4 audio
  mixer, so it reaches a world only when its server runs 1.1.4.

## Scripts and the JavaScript API

- **One script engine.** QtScript is gone from the client and the servers, with its switch in Developer > Scripting.
  Every script runs on the WebAssembly engine (the JavaScript guest, `darkride-js.wasm`, now revision `0.17.0-6`).
  Removed with no replacement: `GraphicsMesh.forEachVertex`, `GraphicsMesh.updateVertexAttributes`,
  `Test.profileRange`. `Graphics.getModel()` with an unknown id returns `null`.
- **`Script.load()`** throws `TypeError: not a function` in client entity scripts and in an avatar's scripts; use
  `Script.include()`. Scripts under a world's rules (entity scripts, an avatar's scripts) start no other script.
- **Scripts load only public files**: an entity script, and anything a script includes, requires or requests, must not
  be a file marked Private in My Files.
- **userData and materialData: keep each value under 1,200 bytes.** `Entities.addEntity` and `Entities.editEntity`
  refuse a change whose values don't fit one entity packet (`libraries/entities/src/EntitySizeCheck.cpp`); an add
  returns no entity, an edit is ignored, and the log says which value was too long. Before 1.1.4 a value over 64 KB was
  saved cut short. Put long data in a file and load it.
- The scripting console runs a line on the WebAssembly engine (guest revision 6, `console_eval`).
- `tablet.toolbarMode` set from a script works; an `Assets.putAsset` callback right after joining runs; an upload with
  no answer fails instead of waiting; stopping a script works while it is starting.
- Shadows: a zone's `shadowBias` default (0.5) is tuned anew; worlds that changed it should check it again.

## Qt 6

- Caitlyn's 1.1.4 release is built on **Qt 6.11.3** (Windows: MSVC 2022, runtime 14.44; Mac: macOS 13 or later).
- The source builds with Qt 5.15 or Qt 6: CMake's `QT_VERSION_MAJOR` chooses (default `5`, "until the Qt 6 build
  works"; Caitlyn's GitHub CI still builds Qt 5.15.2). Qt 6 builds use the QML files' `+qt6` twins (31 files), selected
  at run time.
- For QML written for Darkride (tablet apps, overlays): on Qt 6, `QtGraphicalEffects` is
  `Qt5Compat.GraphicalEffects`. A QML file that must run on both and uses something Qt 6 moved needs a `+qt6` twin
  beside it, as the engine's own do. HTML/EventBridge pages are unaffected.

## Avatars and VRM

- New Avatar menu: what you wear, Recent (five), My Avatars (one searchable list, Favorites first), and a picture of
  each avatar taken automatically and kept on that computer. "Wear from Link…" is now "Paste an Avatar Link…".
- `AvatarBookmarks.addBookmarkForLink` adds a Favorite for a link.
- Model readers take their FST mapping as `hifi::VariantMultiHash` (was `QVariantHash`): C++ that calls
  `AssimpSerializer::read` or another serializer passes `hifi::VariantMultiHash()`.
- Avatars from Unity packages with unusual names import correctly.
- darkride-builds keeps its VRM support (spring bones, MToon, expressions that blend several morph targets, humanoid
  joint names on animations) on top of 1.1.4.

## Building

- **Qt 5 (default):** nothing new. Qt 5.15.2 msvc2019_64 as before (`D:/DarkrideDeps/qt/5.15.2/msvc2019_64` here),
  without the `qtscript` module, which nothing uses now. No vcpkg port changed between 1.1.3.1 and 1.1.4.
- **Qt 6 (to match Caitlyn's release):** configure with `-DQT_VERSION_MAJOR=6` and `QT_CMAKE_PREFIX_PATH` set to the
  Qt 6 `lib/cmake` folder (a new build folder: the prefix path can't change in an existing one). Modules: qtbase,
  qtdeclarative, qtsvg, qttools (LinguistTools), qttranslations, qtmultimedia, qtwebchannel, qtwebsockets,
  qtpositioning, qtshadertools, qtimageformats, qt5compat (the QML twins' `Qt5Compat.GraphicalEffects`) and
  qtwebengine. The Windows Qt 6.11.3 is built with MSVC 2022 14.44; Visual Studio 2022 with that toolset or newer
  matches it. Qt 6.11.3 for Windows is installed here at
  `D:/DarkrideDeps/qt/6.11.3/msvc2022_64` (aqtinstall 3.3.0 can't read Qt 6.11's repository layout; it was fetched
  from download.qt.io directly, checked against the published SHA-1s).
- **The JavaScript guest** is fetched by CMake (`cmake/macros/CopyJavaScriptGuest.cmake`): `darkride-js-0.17.0-6.wasm`
  from `cdn.darkride.ai/deps`, checked by SHA-256, unless `$DARKRIDE_JS_WASM` names one or
  `../downloads/darkride-js-0.17.0-6.wasm` sits beside the checkout. Configuring stops without it. It is copied to
  `resources/wasm/` beside the client and the assignment client.
- **QuaZip** is fetched from GitHub at configure time (v1.x, SHA-256 checked) and built with the matching Qt.
- Linux: Qt 6 builds include `interface/src/LinuxQtX11Display.h` first (X11's `Display` name clash).
- Windows, Qt 6: `windeployqt` runs without `--no-angle`; UNICODE stays off as on Qt 5.

## What darkride-builds changed in the merge

Six files conflicted; the side kept for each:

| File | Kept |
|---|---|
| `cmake/macros/SetupQt.cmake` | Caitlyn's Qt 5/6 version detection, with ours: a distribution's Qt (Ubuntu, headers apart from the libraries) still works, for Qt 5 or 6 |
| `libraries/animation/src/AnimationCache.cpp` | hers (`VariantMultiHash`), with our humanoid joint naming of animations |
| `libraries/fbx/src/AssimpSerializer.cpp` | ours: every FST blendshape line for a name, so VRM expressions blend several targets |
| `libraries/script-engine/src/ScriptEngine.cpp` | hers: the QtScript engine is gone |
| `libraries/script-engine/src/WasmScriptEngine.cpp` | hers, with our restricted-thread mark for every script under a world's rules (entity scripts and an avatar's scripts) |
| `libraries/shared/src/shared/FileLogger.cpp` | hers, with our log file name `darkride-log_*.txt` |

Also:

- `AvatarImporter.cpp` and `tools/auto-rig` pass `hifi::VariantMultiHash()` to `AssimpSerializer::read`.
- `release.yml`: the step that took the JavaScript guest from the 1.1.3.1-beta server tarball is gone (CMake fetches
  the right one); `qtscript` is no longer installed on Windows or macOS, nor `qtscript5-dev` in the server image.
- Kept as they were: the rebrand, `docker/server` (`install-server.sh` still copies the guest into
  `resources/wasm`), `release.yml`, the installer, macOS deployment target 15.0 in our CI, and the world-script
  restrictions.
- No frozen vehicle-path code differs from Caitlyn's 1.1.4. In `MyAvatar.cpp`/`.h`, a partly frozen file, our
  differences are in `useFlow`, `getFlowData` and documentation links, which aren't frozen.

## Testing on this PC

The shared test build (`D:/Data/Darkride/current-build.json`) is the Qt 6 build of `darkride-builds-1.1.4`
(`5e72da5fa9`) in `D:/Data/GithubRepos/dr-builds/build-114-qt6`, which passed QA (task 854). Nobody rebuilds that

### Local worlds get no entity scripts from localhost

Since `v1.1.2-beta` the entity server refuses an entity's `script` and `serverScripts` URL whose host is reserved:
`localhost` and other loopback names, a single-label host, a private IPv4 or IPv6 address
(`libraries/entities/src/ScriptAddressCheck.cpp`; checked on edit in `EntityTree.cpp` near line 2100, and when a saved
world loads near line 3425). The entity loads without its script, and the server log says:

```
Entity {…} loaded without its script, which has 'a reserved host name' : …
```

So a local test world whose assets are served from localhost (for example `run-local.ps1`, assets on port 40190) runs
no entity scripts on a 1.1.2 or later server. `v2026.10.8` (1.1.1) did not have this check.

Workaround: serve the assets under a multi-label name that isn't reserved, such as a hosts-file entry
`127.0.0.1 assets.madders.test` (not `.local` or `.localhost`), and rewrite the world's URLs to that name.
